# Практична робота №8 — Агрегатні функції
## Варіант 1: Бібліотека

Використано базу з Практичної №7. Структура таблиць не змінювалася.

### Завдання 1. COUNT(*) проти COUNT(колонка)
У таблиці `loans`:
- `COUNT(*)` = **7** — кількість усіх записів видачі.
- `COUNT(return_date)` = **4** — кількість записів, де дата повернення не `NULL`.
- Кількість `NULL` у `return_date` = **3**.

Числа відрізняються, отже є видачі, для яких дату повернення ще не заповнено. `COUNT(*)` рахує рядки, а `COUNT(return_date)` пропускає `NULL`.

### Завдання 2. SUM і AVG
Для `books.copies_count` отримано:
- `SUM(copies_count)` = **22**.
- `AVG(copies_count)` = **3.142857142857143**.
- `COUNT(copies_count)` = **7**.

Сума показує загальну кількість примірників усіх книг у бібліотечному фонді, а середнє — скільки примірників припадає на одну книгу в середньому.

### Завдання 3. MIN/MAX на тексті та даті
Для назв книг:
- `MIN(title)` = **Захар Беркут**.
- `MAX(title)` = **Чорна рада**.

SQLite порівнює текстові значення за правилами сортування (collation); за стандартного `BINARY` порівняння використовується порядок кодових значень символів, а не довжина слова чи його значення.

Для дат видачі у форматі ISO `YYYY-MM-DD`:
- `MIN(loan_date)` = **2026-10-01**.
- `MAX(loan_date)` = **2026-10-17**.

Оскільки дати записані у форматі рік-місяць-день із нулями на початку, їхній лексикографічний порядок збігається з хронологічним: спочатку порівнюється рік, потім місяць, потім день.

### Завдання 4. Кілька агрегатів в одному запиті
Запит по всій таблиці `loans` повернув:
- `total_loans` = **7** — усі записи видач.
- `returned_loans` = **4** — видачі з указаною датою повернення.
- `first_loan_date` = **2026-10-01** — найраніша дата видачі.
- `last_loan_date` = **2026-10-17** — найпізніша дата видачі.
- `avg_loan_days` = **15.75** — середня тривалість видачі в днях серед рядків із заповненою датою повернення.

`AVG` ігнорує `NULL`, тому незавершені видачі не входять до середньої тривалості.

### Завдання 5. Агрегат + WHERE
Для книг жанру **Роман**:
- `loan_count` = **2**.
- `returned_count` = **2**.

Після додавання `WHERE b.genre = 'Роман'` до розрахунку потрапляють лише видачі книг жанру «Роман»; інші жанри виключаються, тому агрегатні значення рахуються на меншій вибірці.

### Контрольні питання

1. `COUNT(*)` рахує кожен рядок таблиці незалежно від значень у стовпцях. `COUNT(колонка)` рахує лише рядки, де ця колонка не `NULL`. `COUNT(id)` практично дорівнює `COUNT(*)`, якщо `id` — первинний ключ, оскільки первинний ключ не може бути `NULL`.
2. Знаменник для `AVG` дорівнював би **4**, а не 5: `AVG` ігнорує рядки, де числова колонка має `NULL`, і ділить суму на кількість ненульових значень.
3. Якщо всі значення аргументу `SUM` дорівнюють `NULL`, результат — **`NULL`**, а не 0 і не помилка. Це перевірено запитом `SUM(NULLIF(copies_count, copies_count))`: `NULLIF(x,x)` повертає `NULL` для кожного рядка, тому `SUM` не має жодного ненульового значення для підсумовування.

### Підсумок
Агрегатні функції виконані на фактовій таблиці `loans` і вимірній таблиці `books`. Продемонстровано різницю між `COUNT(*)` і `COUNT(колонка)`, поведінку `SUM`/`AVG` з `NULL`, текстове та хронологічне порівняння `MIN`/`MAX`, а також вплив `WHERE` на агрегатний звіт.
